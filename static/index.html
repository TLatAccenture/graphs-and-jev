The problem

The models are ready. The estate is not.

Many systems, no single map

Each system has its own interface, credentials and quirks. How they connect lives in people's heads and in one-off scripts. Give an agent too little and it acts blind. Give it everything and it slows down, costs more and makes confident mistakes.

Why now

Bigger context windows do not fix this.1 Models still miss what sits in the middle of a long prompt,2 and every tool definition takes space before the agent has done any work.3 Effective context therefore has to be selected, not simply accumulated.4

MCP provides a standard protocol for connecting agents to tools and resources.5 Stripe shows where this can go: its coding agents merge over a thousand pull requests a week,6 drawing on one central MCP server reported to hold over 400 tools.7 Enterprise migration is the next application of that pattern.

The approach

Five layers. One way of working.

It starts with the stack you already run. The MCP Tool Shed defines governed connectivity. System 1 and Jev filter routine noise and gate bounded actions, so ADK with Gemini can spend System 2 reasoning on higher-level migration decisions. Spanner Graph supplies context, while BigQuery and Looker measure the outcome. These product roles form the planned reference architecture, not the live demo.

Select a layer to open it.

  1. Storage in AWS and Azure, SAP, Salesforce, Databricks, ServiceNow, Atlassian and years of Word, Excel and PowerPoint files in Microsoft 365. Nothing is ripped out on day one. In the planned reference architecture, Cloud Storage provides a landing zone for raw documents and source objects.

  2. In the planned reference architecture, systems sit behind governed MCP servers with scoped, short-lived credentials and an audit trail. Compute Engine is one possible host where persistent processes, specialised runtimes or network placement require it. MCP is the protocol and tool boundary, not a parser. The current demo does not run MCP servers.

    Go deeper: MCP Tool Shed

  3. Jev, TypeSafe's System 1 decision model, returns a typed decision with a calibrated confidence in 70 to 500 ms (TypeSafe, vendor-reported). It routes requests, classifies data and gates bounded actions. It filters routine noise so Gemini can reason about higher-level migration decisions. It does not stop a model hallucinating; it stops an unsure output becoming an action.

    In the planned reference architecture, AlloyDB AI can call TypeSafe's hosted Jev API through AI functions and Model Endpoint Management. Jev remains a hosted TypeSafe service and is not embedded in AlloyDB. DiffusionGemma can implement the same discriminative-model API separately on Compute Engine or Cloud Run.

    Go deeper: System 1

  4. Agent Development Kit (ADK) with Gemini is the planned System 2 orchestration layer. Skills provide tested playbooks and ADK coordinates agents and tool use. Deterministic hooks validate schemas, block unsafe actions and request approval. The agents can be built and deployed through Gemini Enterprise Agent Platform. None of these services decides the current demonstrations.

    Managed retrieval: Google Cloud RAG Engine. It is the planned retrieval layer for document parsing and retrieval where suitable. It is not connected to this demo.

    Context fabric: Spanner Graph. It records what feeds what and what each business term means. Agents check upstream and downstream before they change anything, so a fix in one place does not break a report in another.

    Go deeper: skills and hooks · Go deeper: context fabric

  5. In the planned reference architecture, BigQuery stores normalised and analytical data, eval records and telemetry. Looker reports outcomes, quality and cost, including cost per migrated object. The current demonstrations do not write these records to Google Cloud.

Terms

MCP
Model Context Protocol. The open standard for connecting agents to tools and live systems (MCP specification).
MCP server
Exposes one system, such as a CMDB or data warehouse, to agents.
MCP Tool Shed
The governed set of MCP servers; each agent gets only what its task needs.
Skill
A playbook an agent loads for one task, such as migrating a table.
Hook
A check before or after a tool call that can block it.
System 1 model
A small, fast model that returns a typed decision with a confidence, not free text (TypeSafe). Jev is an example.
Context fabric
The shared graph, here Spanner Graph, that agents query for lineage and meaning.
Modernisation Springboard
The BigQuery destination: migrated data, telemetry, audit logs and eval records.
Lineage graph
A graph of what feeds what: tables, jobs, files and reports.
Eval record
A log of one agent step: decision, confidence, tools, tokens, latency, outcome.

Where to start

Start with one pattern. Scale on evidence.

  1. Map the estate

    What do we hold, and what depends on what?

    Connect the first systems through the MCP Tool Shed and build the lineage graph for one domain. The estate stops being tribal knowledge.

  2. Prove one pattern

    Can agents do this safely, end to end?

    Pick one migration pattern, such as SAP tables to BigQuery. Encode it as a skill with deterministic hooks, put a System 1 gate in front of every step and test it against the planned ADK with Gemini orchestration layer.

  3. Scale with evidence

    What worked, and what did it cost?

    In the planned reference architecture, eval records in BigQuery would show what proceeded, what was escalated and the cost per object. Add patterns and systems from there.

Governance

Built to show its working, and to say no.

  • Least privilegeAgents get only the servers and scopes their task needs.
  • Refusal before tool callUnsafe requests stop before any server is called.
  • Bounded outcomesProceed, ask, refuse, escalate or no data.
  • TraceableEvery outcome returns its lineage path and evidence.
  • MeasuredEvery step writes an eval record.
  • PortableThe same pages run on in-browser sample data or a live service on Cloud Run. Switching is configuration, not code.

The demos use a small in-memory graph and fixed rules. They are illustrative, not a production tool.
