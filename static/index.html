Agentic migration and modernisation

Give migration agents the right tools for the job.

Enterprise estates span AWS, Azure, SAP, Salesforce, Databricks, ServiceNow and decades of Microsoft 365 files. The MCP shed gives each migration agent only the tools its task needs, and counts the cost of the work and of the result.

The problem

Too many systems, too much context.

Many systems, no single map

Each system has its own interface and credentials. How they connect lives in people's heads and one-off scripts. Give an agent too little and it acts blind. Give it everything and it slows down, costs more and makes confident mistakes.

Why now

Context windows keep growing (Google, long context), but models still miss what sits mid-prompt (Lost in the Middle), and tool definitions eat the window (Anthropic, code execution with MCP; Anthropic, context engineering). MCP is now the standard way to connect agents to tools (MCP specification). Stripe's coding agents merge over a thousand pull requests a week (Stripe) through one MCP server with over 400 tools (VirtusLab, secondary report). Enterprise migration is next.

The approach

Five pillars, one stack.

A governed set of MCP servers at the base. Above it: a lineage graph, enforced playbooks, fast decision gates, and measurement of what agents did and what it cost.

Select a layer to open it.

  1. Every system sits behind an MCP server with scoped, short-lived credentials and an audit trail. Agents get only the servers their task needs: less context, no secrets in scripts.

    Go deeper: connectivity

  2. Spanner Graph or another graph engine records what feeds what, and what each business term means. Agents check upstream and downstream before they change anything.

    Go deeper: relational context

  3. Skills give agents a playbook per migration pattern. Hooks run around each tool call to validate schemas, block unsafe actions and require approval. Less drift, fewer broken schemas.

    Go deeper: logic

  4. Jev, TypeSafe's System 1 decision model, returns a typed decision with a calibrated confidence in 70 to 500 ms (TypeSafe, vendor-reported). That is fast enough to sit in front of every tool call. It does not stop hallucination; it stops an unsure output becoming an action.

    Go deeper: reflexes

  5. Every step writes an eval record: decision, confidence, tools, tokens, latency, outcome. BigQuery and Looker report it, including cost per migrated object.

    Go deeper: visibility and cost

Terms

MCP
Model Context Protocol. The open standard for connecting agents to tools and live systems (MCP specification).
MCP server
Exposes one system, such as a CMDB or data warehouse, to agents.
MCP shed
The governed set of MCP servers; each agent gets only what its task needs.
Skill
A playbook an agent loads for one task, such as migrating a table.
Hook
A check before or after a tool call that can block it.
System 1 model
A small, fast model that returns a typed decision with a confidence, not free text (TypeSafe). Jev is an example.
Lineage graph
Nodes and edges recording what feeds what.
Eval record
A log of one agent step: decision, confidence, tools, tokens, latency, outcome.
