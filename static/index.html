The problem

The models are ready. The estate is not.

Many systems, no single map

Each system has its own interface, credentials and quirks. How they connect lives in people's heads and in one-off scripts. Give an agent too little and it acts blind. Give it everything and it slows down, costs more and makes confident mistakes.

Why now

Bigger context windows do not fix this.1 Models still miss what sits in the middle of a long prompt,2 and every tool definition takes space before the agent has done any work.3 Effective context therefore has to be selected, not simply accumulated.4

MCP provides a standard protocol for connecting agents to tools and resources.5 Stripe shows where this can go: its coding agents merge over a thousand pull requests a week,6 drawing on one central MCP server reported to hold over 400 tools.7 Enterprise migration is the next application of that pattern.

Google Cloud reference architecture

One agent orchestrates every phase.

The Gemini Migration Agent coordinates the work, reasons over evidence, proposes plans and calls governed tools. It does not copy bytes, parse exact formats, count rows or bypass approvals: deterministic services, code and SQL do that. The phases follow Google's migration framework and its migration documentation. The demonstrations below show its gate pattern today, with deterministic rules making each decision. The agent and the Google Cloud services in this section are a blueprint and are not part of this public demo.

What moves, from where, to where

Destination is chosen by workload. Not all data belongs in BigQuery. Each lane is a representative reference path, not an automatic recommendation. In every lane, deterministic checks produce the evidence and Gemini interprets it.

  1. Unstructured documents Representative blueprint path

    Source
    Microsoft 365, Amazon S3 and Azure Blob Storage.
    What moves
    PDFs, Office files and images.
    Movement or service
    Storage Transfer Service where its documented sources fit, such as Amazon S3 and Azure Blob Storage. Microsoft 365 needs its own export path.
    Destination
    Landing Cloud Storage Retrieval Google Cloud RAG Engine Analytics BigQuery, optional
    Validation or evidence
    Code checks object counts, checksums and metadata.

  2. Spreadsheets and tabular files Representative blueprint path

    Source
    Excel and CSV files in Microsoft 365, Amazon S3 and Azure Blob Storage.
    What moves
    Sheets, tables, schemas and metadata.
    Movement or service
    A documented transfer into a Cloud Storage landing zone, then deterministic loaders and SQL.
    Destination
    Landing Cloud Storage Analytics BigQuery
    Validation or evidence
    SQL counts rows, validates schemas and reconciles totals. RAG is not the row counter.

  3. Operational relational data Representative blueprint path

    Source
    PostgreSQL, Oracle, SQL Server and SAP-backed data.
    What moves
    Tables, change streams, schema and state.
    Movement or service
    Database Migration Service or Datastream, only where documented for the exact source and target. SAP needs a path chosen for the specific system.
    Destination
    Operational AlloyDB for PostgreSQL Analytics BigQuery
    Validation or evidence
    Schema, row, change-lag and integrity checks.

    AlloyDB AI can call TypeSafe's hosted Jev API through AI functions and Model Endpoint Management in the blueprint. Jev is not stored or hosted in AlloyDB.

  4. Applications and jobs Representative blueprint path

    Source
    Virtual machines, Spark and Hadoop jobs, containerisable apps.
    What moves
    Workloads, binaries and configuration. Not data.
    Movement or service
    Migrate to Virtual Machines and Migrate to Containers for their documented paths; workload-specific tooling for Spark and Hadoop.
    Destination
    Machines Compute Engine Jobs Dataproc or GKE Stateless Cloud Run
    Validation or evidence
    Health, behaviour, performance and rollback checks.

MCP exposes tools and resources. Deterministic code or SQL parses exact formats, counts rows and validates schemas. The current demo does not run MCP servers.

The approach

Five capabilities the agent uses.

The Gemini Migration Agent starts from the stack you already run. It reaches systems through the MCP Tool Shed, lets Jev filter routine decisions so Gemini can reason about the hard ones, and measures every outcome. These roles make up the blueprint.

Select a capability to open it.

  1. Storage in AWS and Azure, SAP, Salesforce, Databricks, ServiceNow, Atlassian and years of Word, Excel and PowerPoint files in Microsoft 365. Nothing is ripped out on day one. In the blueprint, Cloud Storage provides a landing zone for raw documents and source objects.

  2. In the blueprint, systems sit behind governed MCP servers with scoped, short-lived credentials and an audit trail. Compute Engine is one possible host where persistent processes, specialised runtimes or network placement require it. MCP is the protocol and tool boundary, not a parser. The current demo does not run MCP servers.

    Go deeper: MCP Tool Shed

  3. Jev, TypeSafe's System 1 decision model, returns a typed decision with a calibrated confidence in 70 to 500 ms (TypeSafe, vendor-reported). It routes requests, classifies data and gates bounded actions. It filters routine noise so Gemini can reason about higher-level migration decisions. It does not stop a model hallucinating; it stops an unsure output becoming an action.

    In the blueprint, AlloyDB AI can call TypeSafe's hosted Jev API through AI functions and Model Endpoint Management. Jev remains a hosted TypeSafe service and is not embedded in AlloyDB. DiffusionGemma can implement the same discriminative-model API separately on Compute Engine or Cloud Run.

    Go deeper: System 1

  4. Agent Development Kit (ADK) with Gemini is the System 2 orchestration layer in the blueprint. Skills provide tested playbooks and ADK coordinates agents and tool use. Deterministic hooks validate schemas, block unsafe actions and request approval. The agents can be built and deployed through Gemini Enterprise Agent Platform. In the current demonstrations, deterministic rules make every decision.

    Managed retrieval: Google Cloud RAG Engine. It is the managed retrieval layer in the blueprint, for document parsing and retrieval where suitable. It is not connected to this demo.

    Context fabric: Spanner Graph. It records what feeds what and what each business term means. Agents check upstream and downstream before they change anything, so a fix in one place does not break a report in another.

    Go deeper: skills and hooks · Go deeper: context fabric

  5. In the blueprint, BigQuery stores normalised and analytical data, eval records and telemetry. Looker reports outcomes, quality and cost, including cost per migrated object. Today the service logs one structured line per API request; BigQuery eval records and Looker reports are part of the blueprint.

Terms

MCP
Model Context Protocol. The open standard for connecting agents to tools and live systems (MCP specification).
MCP server
Exposes one system, such as a CMDB or data warehouse, to agents.
MCP Tool Shed
The governed set of MCP servers; each agent gets only what its task needs.
Skill
A playbook an agent loads for one task, such as migrating a table.
Hook
A check before or after a tool call that can block it.
System 1 model
A small, fast model that returns a typed decision with a confidence, not free text (TypeSafe). Jev is an example.
Context fabric
The shared graph that agents query for lineage and meaning: Spanner Graph in the blueprint, a small sample graph in the demos.
Modernisation Springboard
The BigQuery destination: migrated data, telemetry, audit logs and eval records.
Lineage graph
A graph of what feeds what: tables, jobs, files and reports.
Eval record
A log of one agent step: decision, confidence, tools, tokens, latency, outcome.

Where to start

Start with one pattern. Scale on evidence.

  1. Assess

    What do we hold, and what depends on what?

    Connect the first systems through the MCP Tool Shed and map one domain's lineage. The estate stops being tribal knowledge.

  2. Plan

    Which path, in which order, with what rollback?

    Pick one pattern, such as SAP tables to BigQuery. Encode it as a skill with deterministic hooks. A person approves the plan.

  3. Deploy

    Did it arrive intact?

    Deterministic jobs move and validate the data. Jev gates each step, and a failed validation rolls back.

  4. Optimise

    What worked, and what did it cost?

    In the blueprint, eval records in BigQuery show what proceeded, what was escalated and the cost per object.

Governance

Built to show its working, and to say no.

The agent's design rules. The demos already show refusal, bounded outcomes, traceability and portability.

  • Least privilegeAgents get only the servers and scopes their task needs.
  • Refusal before tool callUnsafe requests stop before any server is called.
  • Approval before DeployA person approves the plan before anything moves.
  • Bounded outcomesProceed, ask, refuse, escalate or no data.
  • TraceableEvery outcome returns its lineage path and evidence.
  • MeasuredEvery step writes an eval record.
  • PortableThe same pages run on in-browser sample data or a live service on Cloud Run. Switching is configuration, not code.

The demos run fixed rules over a small in-memory graph, so every result is repeatable. They illustrate the pattern and are not a production tool.
